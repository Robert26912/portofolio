FILE dashboard.html — App Shell ▶

The interactive app. Provides empty containers (#tileGrid, #detailModal) that JavaScript fills dynamically. Loads two scripts in order: tools.js then module-loader.js.

IN User clicks "Dashboard →" from landing page
OUT Renders tiles, modals, interactive tools to DOM
USES dashboard.css, module-loader.js, tools.js
CHILD <header> — back link, title, tag
CHILD <input#searchInput> → JS listens for 'input' event
CHILD <button.filter-btn> × 4 → JS listens for 'click'
CHILD <section#tileGrid> — EMPTY, JS fills with tiles
CHILD <div#detailModal> — hidden overlay, JS shows/hides
CLASS module-loader.js — ModuleLoader Class ▶

The brain. A single ES6 class that: discovers module data from JSON, creates DOM elements, handles all user interaction (search, filter, modal). It self-initializes on load.

IN <script> tag in dashboard.html loads this file
IN fetch('config/modules-bundle.json') → gets module data
IN DOM events: input, click, keydown from user
OUT Creates tile <div> elements → appends to #tileGrid
OUT Sets innerHTML of #modalBody → shows modal
OUT Calls DevTools.loadTool() via onclick in modal HTML
STATE this.modules[] — array of loaded module objects
STATE this.currentFilter — 'all' | 'projects' | 'tools' | 'iot'
STATE this.currentSearch — string from search input
FN constructor() → init() → setup()
FN discoverModules() → fetch bundle or fallback
FN renderTiles() → getFilteredModules() → createTile()
FN openModule(mod) → build HTML string → set modal
FN setupEventListeners() → search, filters, modal close
OBJECT tools.js — DevTools Object ▶

A global object with sub-objects for each tool (calculator, jsonFormatter, base64). Each tool has a render() method that returns HTML and action methods that manipulate DOM elements inside that HTML.

IN ModuleLoader calls DevTools.loadTool('calculator')
IN onclick="" attributes in rendered HTML call DevTools.calculator.appendNumber() etc.
OUT Sets workspace.innerHTML with tool UI
OUT Updates #calcDisplay, #jsonOutput, #base64Output
CHILD calculator: { render(), appendNumber(), setOperator(), calculate(), clear() }
CHILD jsonFormatter: { render(), format(), minify(), validate() }
CHILD base64: { render(), encode(), decode() }
DATA config/modules-bundle.json — Module Registry ▶

Single JSON file containing ALL module metadata + content. The "database" of the system. One HTTP request loads everything. Fallback: modules.json registry + individual module.json/content.json files.

IN Hand-edited by developer (you) in text editor
OUT ModuleLoader.discoverModules() reads this via fetch()
SHAPE { modules: { [id]: { id, title, description, icon, category, visibility, enabled, interactive?, content: { summary, projects[], skills[], interests[], tools[], learning_notes } } } }
PATTERN modules/[name]/ — Module Folders (Fractal Unit) ▶

Each module folder is a self-contained unit. It has config (module.json), data (content.json), and optionally logic (tools.js). This is your fractal pattern — same structure at every level. Adding a module = creating a folder + registering it.

IN Referenced by modules-bundle.json (fast) or modules.json (fallback)
OUT Data flows to ModuleLoader → rendered as tile + modal
CONFIG module.json — id, title, icon, category, enabled, visibility
DATA content.json — summary, projects[], skills[], learning_notes
LOGIC [optional] tools.js, tracker.js, etc. — interactive behavior
STYLE style.css + dashboard.css — Design System ▶

Two separate CSS files — one per page. They share the same CSS custom properties (variables) for colors, fonts, spacing. style.css handles the landing page, dashboard.css handles the app.

IN Loaded by <link> tags in HTML <head>
OUT Controls all visual rendering — layout, colors, animation
SHARED :root variables — --bg, --accent, --font, --border, etc.
UNIQUE style.css — hero, about-grid, timeline, contact-grid
UNIQUE dashboard.css — tiles, modal, tools, calc-buttons
FLOW Complete Data Flow — What Happens When ▶

The full journey of data from file to screen.

1 Browser loads dashboard.html → parses HTML
2 Browser loads dashboard.css → applies styles
3 Browser loads tools.js → DevTools object exists globally
4 Browser loads module-loader.js → new ModuleLoader() runs
5 constructor() → init() → checks DOM ready → setup()
6 setup() → discoverModules() → fetch('modules-bundle.json')
7 GitHub CDN responds with JSON → parsed → pushed to this.modules[]
8 renderTiles() → getFilteredModules() → createTile() × 6
9 Each tile → addEventListener('click') → openModule(mod)
10 setupEventListeners() → search input, filter buttons, modal close
USER Types in search → input event → this.currentSearch = value → renderTiles()
USER Clicks filter → click event → this.currentFilter = category → renderTiles()
USER Clicks tile → openModule(mod) → build HTML → set modalBody → show modal
USER Clicks "Open" tool → DevTools.loadTool() → render() → workspace.innerHTML

System as Pseudo Code

The entire application logic in readable pseudo code. This maps 1:1 to the real JavaScript.

// ===== STARTUP SEQUENCE =====
WHEN browser loads dashboard.html:
load dashboard.css → apply styles
load tools.js → DevTools exists in memory
load module-loader.js → creates new ModuleLoader()

// ===== MODULE LOADER =====
CLASS ModuleLoader:

STATE: modules = [], filter = 'all', search = ''

ON CREATE:
wait for DOM ready
find #tileGrid element
CALL discoverModules()
CALL renderTiles()
CALL setupEventListeners()

FUNCTION discoverModules():
TRY fetch 'config/modules-bundle.json'
FOR EACH module in bundle.modules:
IF module.enabled → push to this.modules[]
CATCH → fallback to individual files
fetch 'config/modules.json' → get list of names
FOR EACH name:
fetch 'modules/{name}/module.json'
fetch 'modules/{name}/content.json'
merge and push to this.modules[]

FUNCTION renderTiles():
clear #tileGrid
filtered = getFilteredModules()
IF filtered empty → show "no results"
FOR EACH module in filtered:
tile = createTile(module)
append tile to #tileGrid

FUNCTION getFilteredModules():
RETURN this.modules WHERE:
enabled == true
AND (filter == 'all' OR category == filter)
AND (search empty OR title/description contains search)

FUNCTION createTile(module):
create <div class="tile">
set data-category, data-moduleId
fill innerHTML: icon, title, description, category
ON CLICK → openModule(module)
RETURN tile element

FUNCTION openModule(module):
IF private → alert "needs auth" → return
set modal icon, title, category

IF module.interactive:
build tool buttons HTML
each button → onclick="DevTools.loadTool(type)"
add empty #toolWorkspace div
ELSE:
IF summary → add paragraph
IF projects → build project cards with tech tags + status
IF skills → build skill pills
IF interests → build interest pills
IF learning_notes → add italic note

set #modalBody.innerHTML = built HTML // only ONCE
add 'active' class to modal // only ONCE
disable body scroll

FUNCTION setupEventListeners():
#searchInput → on 'input' → update this.search → renderTiles()
.filter-btn → on 'click' → update active class + this.filter → renderTiles()
#modalClose → on 'click' → remove 'active', restore scroll
#modalCloseBtn → on 'click' → same
.modal-backdrop → on 'click' → same
document → on 'Escape' key → same

// ===== DEV TOOLS =====
OBJECT DevTools:
FUNCTION loadTool(type):
SWITCH type:
'calculator' → html = calculator.render()
'json-formatter' → html = jsonFormatter.render()
'base64' → html = base64.render()
set #toolWorkspace.innerHTML = html
smooth scroll to workspace

OBJECT calculator: // state: currentValue, previousValue, operator
render() → returns calculator HTML with buttons
appendNumber(n) → updates display, handles decimals
setOperator(op) → stores op, chains calculations
calculate() → prev op current = result
clear() → reset all state

Security Audit

Current state is a static site served by GitHub Pages. Here's what matters now and what will matter when you add a backend.

✅
HTTPS enforced
GitHub Pages serves over HTTPS by default. All data in transit is encrypted. No action needed.
SAFE
✅
No secrets in code
No API keys, passwords, or tokens in your repository. Your .gitignore exists. Static site needs no secrets.
SAFE
✅
No user input stored
Calculator and tools process data client-side only. Nothing is sent to a server or saved. Zero attack surface for data theft.
SAFE
⚠️
XSS via JSON content
Module data is inserted with innerHTML. If someone injected <script> tags into your JSON files, it could execute. LOW RISK now because only you edit the JSON. HIGH RISK if you ever let users submit content. Fix: sanitize strings or use textContent where possible.
LOW RISK
⚠️
Email address visible in source
robert0hidri@gmail.com is in the HTML source. Bots can harvest it for spam. Consider: use a contact form (needs backend), or obfuscate the email with JavaScript encoding.
LOW RISK
✅
External links use rel="noopener"
Your GitHub and LinkedIn links include rel="noopener" which prevents the linked page from accessing your page's window object. Correct security practice.
SAFE
ℹ️
No Content Security Policy (CSP)
A CSP header tells the browser which scripts/styles are allowed to run. Not critical for a static site, but adding one is best practice. GitHub Pages supports it via a meta tag.
OPTIONAL
🔮
PHASE 2: Authentication needed
When you add private modules and a backend: use proper password hashing (bcrypt), JWT tokens, HTTPS-only cookies, rate limiting on login endpoints. Never store plain passwords.
FUTURE
🔮
PHASE 2: Input validation
When you accept user input (forms, file uploads): validate on BOTH client and server. Never trust client-side validation alone. Sanitize all data before storing or displaying.
FUTURE
